## 一、执行摘要

### 1.1 总体判断

项目已形成较完整的技能协作架构和治理工具链，但当前证据不足以证明其已经达到工程应用可靠性要求。

建议保留“总入口调度＋专项技能＋标准推理＋声学估算＋独立校验”的总体架构，将下一阶段的重点从文件完整性和流程完整性，转向以下三个结果：

1. **专业结论有依据**：公式、参数、评价量、算例和精度声明相互一致，并有独立来源支持。
2. **调用行为有实证**：技能不仅写明调用与降级规则，而且在宿主真实执行中遵守这些规则。
3. **输出边界不失真**：估算不升级为实测，内部一致不升级为工程合规，建议不升级为结构或消防安全结论。

当前更适宜将项目定位为有明确使用边界的工程咨询知识库；在模型校准与行为验证完成前，不宜将其整体认定为已验证的工程计算引擎。

### 1.2 优先关注事项

| 优先级 | 事项 | 主要原因 |
|---|---|---|
| 高 | 声学模型、单位、构造拓扑及算例复核 | 可能直接改变估算结果和方案判断 |
| 高 | 无依据的现场指标换算、达标升级及结构承载判断 | 涉及专业边界与用户误用风险 |
| 高 | PL-046 降级行为复验 | 正文修复尚不能证明宿主稳定执行 |

| 中 | 留痕产生侧与发布边界处理 | 避免历史问题再次进入加载或发布路径 |

## 三、开发意图与架构拆解

### 3.1 项目应交付一条可靠咨询链路

项目的真正目标不是积累十五份技能文本，而是形成以下可执行链路：

```text
用户提出问题
  → 确认项目条件与咨询目标
  → 总入口路由或专项技能直达
  → 识别适用标准与专业边界
  → 开展构造分析、计算或验证
  → 检查跨系统接口与冲突
  → 独立校验
  → 输出结论、证据、限制条件和待确认事项
```

其中，总入口负责调度，不替代专项专业判断；标准推理回答“依据什么分析”，计算模型回答“在指定假设下估算多少”，两者不能互相替代。

### 3.2 五层职责模型

| 层次 | 核心职责 | 主要载体 |
|---|---|---|
| 用户任务层 | 获取条件、识别需求、补足信息 | 用户输入、追问、统一上下文 |
| 调度层 | 分解任务、选择技能、整合输出 | 总入口及交叉路由规则 |
| 专业判断层 | 选型、适用性分析、计算估算 | 部品技能、SRE、ACE |
| 证据层 | 支撑标准状态、参数和结论 | 标准原文、检测报告、计算过程 |
| 维护保障层 | 版本、同步、登记与回归 | 治理文件、同步器、校验器 |

**维护保障层全绿不能推出专业判断正确；正文写了规则也不能推出实际调用遵守规则。**

### 3.3 已有架构的价值与局限

| 已有设计 | 价值 | 仍需承担的验证 |
|---|---|---|
| 总入口与专项技能分离 | 减少协调角色越权判断 | 宿主是否真实路由、整合时是否保持结论原义 |
| 集中接口契约 | 提供共同输入输出结构 | 实际请求与响应是否符合契约、下游是否消费证据 |
| SRE 与 ACE 分工 | 区分标准适用性与物理估算 | 标准依据是否真实、模型是否适用 |
| 三层同步与镜像 | 减少版本漂移 | 同一份内容本身是否正确 |
| 红线与确定性标记 | 限制过度承诺 | 示例和最终输出是否遵守限制 |
| 独立校验与盲评 | 降低生产者自证风险 | 角色、材料与评分过程是否真正独立 |

物理单源解决“是不是同一份文件”，语义单源解决“同一概念是否只有一个权威定义”。即使镜像字节全等，跨技能公式、参数或示例仍可能相互冲突。

## 四、关键发现与整改建议

### F-01 M5 公式、单位与示例结果冲突

**证据状态：E2＋E3；已知遗留 PL-038 的相关问题，不重复计作全新发现。**

声学代理报告：楼地面湿式示例参数 `m′=108、s=10、C=10`，按所载公式复算为 36.60 dB，文档示例约为 21 dB；干式示例 `m′=38、s=10`，复算为 28.44 dB，文档写 15 dB。

代理另指出，共振公式与后续对数式对 N/m³、MN/m³ 的使用边界不清；按其复算，两种单位直接代入相关对数项会相差 60 dB。ACE 与 FL 对浮筑质量是否包含弹性垫自身也存在口径疑点。

**证据定位：**

- `技能仓备份/prefab-floor-system/reference.md:196-236,973-986,1028-1037`
- `技能仓备份/acoustic-calculation-engine/reference.md:218-261`

**建议：**先区分经验区间与公式结果，明确各变量的量纲、单位和质量边界，再核实模型适用性；不能仅把示例值改成复算值后继续宣称达标。

**验证：**单位等价性、示例复算、边界条件与独立检测数据残差分别检查。

### F-02 缝隙损失与吻合频率缺少一致的条件约束

**证据状态：E2＋E3；PL-038 相关问题与分区新增细化。**

代理按 ACE 所载复合隔声公式，取墙体 50 dB、开口 0 dB，缝隙比例 0.01%、0.1%、1% 时复算损失约为 10.41、20.04、30.00 dB，与速查表约 0、2—4、8—12 dB 不一致。该条件下的结果不能扩展为所有缝隙场景的通用值。

代理还报告，按 PW 所列 12 mm 普通石膏板参数范围，吻合频率复算约 2769—3511 Hz，与表内 1950—2450 Hz 不符；ACE 对弯曲刚度因子省略误差的说明也需核对。

**证据定位：**

- `技能仓备份/acoustic-calculation-engine/reference.md:59-95,278-298`
- `技能仓备份/prefab-partition-wall-solution/reference.md:227-285,336-355`

**建议：**速查表绑定墙体、开口和参数条件；吻合频率逐行绑定材料参数。未经证明的普适保证应撤回或收窄。

**验证：**零开口极限、面积比例换算、参数包络与公式完整性。

### F-05 实验室、现场评价量及达标结论可能混用

**证据状态：E3。**

代理指出，ACE 的住宅楼板映射使用 `Ln,w`，FL 目标使用 `L'nT,w`，而 FL 示例将实验室区间转换为现场区间后输出达标结论。ACE 中“Rw+C 通常≥Rw”的描述，与同文件 `Rw=51、Rw+C=47` 的示例也相互冲突。

**证据定位：**

- `技能仓备份/acoustic-calculation-engine/reference.md:403,667-704`
- `技能仓备份/prefab-floor-system/examples.md:105-122,187-195`

**建议：**将评价量、实验室或现场属性、频谱修正、估算或实测性质分别标注。没有经过验证的现场转换模型和必要输入时，不生成现场预测数值；估算不能直接升级为验收达标。

**验证：**检查请求、计算结果、示例及最终结论的评价量是否全程一致；规范限值另行官方核验。

### F-06 MSM 公式形式与构造拓扑混淆

**证据状态：E3。**

代理指出，约化质量形式不要求两叶质量相等，不能将对称近似的限制直接套在约化质量表达上。

在楼地面架空示例中，代理发现将基层板与贴附面层分别当成空气腔两侧质量，遗漏结构楼板。其报告原模型为 84.57 Hz，按示例材料重新构造理想两叶模型为 33.12 Hz；后者未处理支撑脚等因素，不能作为实际工程预测值。

**证据定位：**

- `技能仓备份/acoustic-calculation-engine/reference.md:110-160,196-198`
- `技能仓备份/prefab-floor-system/examples.md:304-346`

**建议：**先建立“叶片—空腔—连接”关系，再选择公式；多叶与多级系统不得未经依据直接叠加增益。

**验证：**对称、非对称、刚性连接、中间叶片及支撑连接等场景分别检查适用边界。

### F-07 吊顶绝对隔声量与贡献量缺少转换依据

**证据状态：E3；涉及历史架构稿，现行契约影响范围待核。**

代理发现，架构 IC-09 示例返回绝对 `Rw+C`，CL 将输出解释为宿主贡献量，并使用经验区间封顶。对绝对隔声量取上限，并不能在物理上把它转换成改善量。

**证据定位：**

- `文档/ACE架构边界与接口契约_v1.0.md:414-485`
- `技能仓备份/prefab-ceiling-system/reference.md:661-685`

**建议：**明确宿主基准、改造前后状态和增量定义。缺少必要条件时，只提供定性机制或明确标注的经验参考。

**验证：**核对现行 IC-09，再验证改造前后使用同一评价量、同一边界和相同基准，而非只检查是否出现“贡献量”字样。

### F-08 M7 区间方向与精度声明缺少充分验证

**证据状态：E3。**

代理报告的主要疑点包括：

- `r<1` 时，20lg 与 40lg 计算出的上下界需要重新排序；例如 `r=0.5` 时约为 `[-12.04,-6.02]`。
- 混入不变龙骨质量可能缩小减重损失，不能一概描述为偏保守。
- 频段内质量控制关系外推到单值评价量，需要处理共振、吻合和频谱变化。
- “与其他模型差值超过阈值则优先 M7”不能替代独立验证。
- 当前回报中的证据不足以支持通用的 ±2—3 dB 精度保证。

**证据定位：**

- `技能仓备份/acoustic-calculation-engine/reference.md:321-416`

**建议：**修正区间排序，明确质量对象，保留基准不确定度；未经独立验证的精度声明标为待验证。

**验证：**采用独立同族样本，按构造族留出评估，报告偏差与区间覆盖率；避免同一批数据既调参又证明准确。

### F-09 示例可能越过结构、耐火与热工判断边界

**证据状态：E3。**

代理报告：

- FL 示例用新增恒荷载小于活荷载标准值判断承载满足；该比较不能证明结构剩余承载能力。
- 地暖示例在缺少热工计算依据时建议功率增加 5%—10%。
- PW 耐火逐层累加模型的精度依据不足，但示例仍输出满足判断。
- 部分逐层厚度合计与总厚度表值不符：FL 所列各层合计 64—70 mm、表列 56—62 mm；PW 所列 `120+4×12=168 mm`、表列约 150 mm。

**证据定位：**

- `技能仓备份/prefab-floor-system/examples.md:124-136,825-843`
- `技能仓备份/prefab-partition-wall-solution/reference.md:439-489`
- `技能仓备份/prefab-floor-system/reference.md:959-980`
- `技能仓备份/prefab-partition-wall-solution/product-solutions.md:68-79`

**建议：**优先复核涉及安全的确定性判断。缺少设计、检测或专业计算依据时，应转为待核验或专业转介；逐层厚度、质量、荷载采用同一构造清单计算。

**验证：**先排除层次重复、取值范围及构造方案差异，再裁定具体算术错误；不得只按摘录修改总值。

### F-11 接口存在不等于请求响应已受约束

**证据状态：E2＋E4。**

既有登记中的 IC-10 请求字段错接，说明集中契约存在时，消费者仍可能抄错。正文修正不能自动证明真实调用没有缺字段、忽略降级证据或提升确定性等级。

**建议：**程序化调用边界复用现有 Schema 校验真实载荷；纯文本调用通过完整转录审计。未确认宿主存在统一拦截点前，不承诺建设全局强制调用网关。

### F-12 冻结指纹与治理登记可能存在过度耦合

**证据状态：E2＋E4；属于待验证风险。**

既有记录显示内容包聚合哈希包含治理登记文件，并曾仅因登记面变化而改变指纹。需进一步核对：行为不变的登记更新，是否会触发不必要的重新冻结或测试失效。

**建议：**区分完整环境归档指纹与行为可比较性指纹，分别定义失配处理规则。不依据摘要直接判定现有冻结机制失效。

## 五、根因分析

以下为分析推断，不是已证实的开发过程事实。

### 5.1 多个手工承载面可能形成多个语义事实源

公式、经验表、示例、产品构造和接口解释分别维护，容易出现某处更新而其他位置保持旧口径。单纯跨层同步会把同一冲突复制得更一致，不能消解冲突。

### 5.2 示例可能抵消正文的谨慎约束

正文强调估算、待确认和专业边界，示例却直接给出达标、承载满足或精确改善量，可能诱导实际输出模仿示例而非遵守原则。

### 5.3 来源可信度与模型精度被混合使用

官方标准、图集或检测报告可以支持特定事实，但不能自动证明某个经验外推模型具有通用精度。必须分别说明“依据来源可信”与“模型预测经过验证”。

### 5.4 治理验证强于专业结果验证

文件一致性、登记完整性和回归工具较完善；但专业参数真值、宿主行为与工程应用效果的独立证据仍不足。下一阶段应调整验证投入，而不是削弱已有有效门禁。

## 七、工具与验证方法

| 验证目标 | 建议手段 | 证据边界 |
|---|---|---|
| 文件与引用关系 | 文件清单、逐段读取、定向搜索 | 搜索命中不能代替完整通读 |
| 公式与算术 | 独立内存复算、量纲检查、参数扫描 | 算术正确不等于模型适用 |
| 标准与条文 | 官方来源核验、原文对照、必要 OCR | OCR 文本不得直接等同原文真值 |
| 契约结构 | 对真实载荷执行现有 Schema 校验 | 字段合法不等于工程语义正确 |
| 宿主行为 | 独立会话、完整转录、授权环境注入 | 单次成功不等于稳定可靠 |
| 内容维护 | 现有九门禁、同步器 | 全绿不等于专业合规通过 |
| 工程适用性 | 独立专业复核、检测或试点对照 | 不能由生产答案的同一角色自证 |

多代理宜按资料核验、模型审查、行为取证、独立评价和协调汇总分工。回报必须附原始证据指针与实际覆盖清单，不以“已完成”自述作为验收依据。
