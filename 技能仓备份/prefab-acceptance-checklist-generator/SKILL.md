# 装配式装修验收清单生成器

> **版本说明（v2.2.0）**：IC-10/SRE 标准推理引擎接线——Step 2 接入 IC-10 动态获取适用标准集，标准匹配从静态查表升级为场景推理；新增多文件认知架构（A/B/C/D/E 分层）、IC-10 集成调用节。

## 1. 角色定位

本技能是**验收清单转化器**，将各专项技能（墙面/吊顶/地面/厨卫/收纳/机电）的技术输出转化为：

- **可检查**：每个检查项有明确的合格标准和检验方法
- **可记录**：每个检查项有记录栏，支持现场填写
- **可整改闭环**：不合格项有整改跟踪机制

**边界声明**：本技能不制定验收标准（标准来自国家/行业规范），不替代监理/质检人员的现场判定，仅提供结构化清单工具。验收判定须由具备相应资格的人员（监理工程师/质量检查员）执行。

## 2. 知识体系

### 2.1 验收阶段分类

| 验收阶段 | 时间节点 | 检查重点 | 参与方 | 数据来源 |
|---|---|---|---|---|
| 材料进场检验 | 材料到场时 | 合格证、检测报告、外观、规格型号、数量 | 施工方+监理 | S1：GB 50210-2018 第3.0.3条 |
| 过程检查 | 施工过程中 | 工序质量、尺寸偏差、工艺合规 | 施工方自检 | S2：施工管理要求 |
| 隐蔽工程验收 | 下道工序覆盖前 | 管线、防水、龙骨、连接件、基层 | 施工方+监理+建设方 | S1：GB 50210-2018 第3.0.5条 |
| 分项工程验收 | 分项完成后 | 各部品系统安装质量、功能 | 施工方+监理 | S1：GB 50210-2018 第4~12章 |
| 竣工交付验收 | 全部完成后 | 功能、观感、资料完整性、整改闭环 | 建设方+施工方+监理+设计 | S1：GB 50210-2018 第3.0.6条 |
| 整改复验 | 整改完成后 | 不合格项整改效果确认 | 施工方+监理 | S2：施工管理要求 |

### 2.2 清单生成规则

每个检查项**必须**包含以下要素：

| 要素 | 说明 | 示例 |
|---|---|---|
| 检查项目 | 具体检查对象/内容 | 轻钢龙骨间距 |
| 合格标准 | 量化的合格判定条件 | 间距偏差≤3mm |
| 检验方法 | 具体检测手段 | 钢尺量测 |
| 依据来源 | 标准条款或设计文件 | GB 50210-2018 第7.2.4条 |
| 记录栏 | 现场填写实测值/结果 | （空白，现场填写） |
| 判定 | 合格/不合格/不适用 | （空白，现场判定） |

**生成原则**：
- 合格标准必须量化或可明确判定（避免"符合要求"等模糊表述）
- 检验方法必须可操作（避免"观察"作为唯一方法，应配合量具）
- 依据来源必须标注具体标准编号和条款号，或标注"设计文件"
- 不编造标准条款号——不确定时标注"参见相关标准，具体条款以设计文件为准"

## 3. 工作流程

### Step 0：确认验收范围

- 确认项目类型（住宅/公寓/酒店/医院/办公）
- 确认验收阶段（材料进场/过程/隐蔽/分项/竣工/整改）
- 确认空间范围（全部楼层/指定楼层/指定户型）
- 确认部品系统范围（全部/指定系统）
- 信息不足时，列出需确认项，不做假设

### Step 1：识别部品系统

- 根据项目信息确定涉及的部品系统
- 调用对应专项技能获取技术要求
- 列出各系统的验收子项

### Step 2：匹配验收标准（IC-10/SRE 集成）

- 调用 IC-10（标准推理引擎），传入项目类型、涉及部品系统、项目所在地，获取适用标准集与推理路径
- 以 SRE 返回的适用标准集为基准，为每个检查项匹配对应标准条款
- 标注数据来源级别（S1/S2/S3）
- 不确定的标注"参见相关标准，具体以设计文件为准"
- 涉及强制性条文的标记为必检项
- **SRE 不可用时降级**：使用本技能 §8 参考标准表 + §2.4 强制性条文检查项执行标准匹配，在清单头部标注"SRE 降级：使用 ACG 内置标准映射，标准集未经场景推理筛选"

### Step 3：生成检查条目

- 按清单生成规则逐项编制
- 确保每项包含：检查项目/合格标准/检验方法/依据来源/记录栏
- 按施工顺序或空间顺序排列
- 必检项置顶或加粗标注

### Step 4：标注来源与分级

- 每条依据标注S1/S2/S3级别
- S1：直接引用标准条款号
- S2：标注"行业通用做法"或"设计文件"
- S3：标注"经验数据，具体以设计文件为准"
- 不编造条款号

### Step 5：输出清单

- 按输出模板格式化
- 附整改闭环表
- 附标准免责提示
- 提示需专业资格人员判定的项目

## 4. 红线体系

以下 13 条红线已注册于红线注册表§十六（全局编号 AC-R-*），完整定义以 `../shared/redlines-registry.md` 为准。

### P0 红线（违反即清单不合格，必须整改）

- **AC-R-P0-1 严禁遗漏强制性条文检查项**：第2.4节所列必检项在任何相关清单中不得缺失
- **AC-R-P0-2 严禁编造验收标准**：不得虚构标准条款号、不得编造不存在的指标值
- **AC-R-P0-3 严禁强制项与一般项级别混淆**：不得将非强制项标注为强制项，或将强制项降级为一般项
- **AC-R-P0-4 严禁遗漏隐蔽工程验收节点**：凡被下道工序覆盖的检查项必须列入隐蔽验收

### P1 红线（重要缺陷，应整改）

- AC-R-P1-1 合格标准未量化（仅写"符合要求"）
- AC-R-P1-2 检验方法不可操作（仅写"观察"无量具）
- AC-R-P1-3 依据来源缺失（无标准编号或"设计文件"标注）
- AC-R-P1-4 检查项覆盖不完整（遗漏部品系统关键检查项）
- **AC-R-P1-5 严禁跳过 SRE 标准推理**：Step 2 必须调用 IC-10（标准推理引擎）获取场景化适用标准集；SRE 不可用时须执行 §11.3 降级流程并在清单头部标注降级标记，不得静默跳过

### P2 红线（一般缺陷，宜优化）

- AC-R-P2-1 检查项排序不合理（未按施工顺序）
- AC-R-P2-2 记录栏格式不统一
- AC-R-P2-3 缺少整改闭环跟踪表
- AC-R-P2-4 缺少现场照片记录提示

### 红线冲突仲裁规则

当清单生成遇到标准冲突或信息矛盾时：
1. 强制性条文 ＞ 推荐性标准 ＞ 行业惯例 ＞ 经验数据
2. 新版本标准 ＞ 旧版本标准（以现行有效版本为准）
3. 设计文件指标严于标准时，按设计文件
4. 无法判定时，标注"待确认"并提示由监理工程师或设计方明确
5. 仲裁结果须在清单备注中说明

## 9. 接口契约（IC-14 接收方）

本技能作为验收清单技能的接收方，遵循接口契约 IC-14（总入口 → 验收清单技能）。完整 Schema 见 `../shared/interface-contracts.md` §4.1 IC-14。

**请求参数**（与 IC-14-Request Schema 字段集一致，Schema 为 additionalProperties:false）：

| 参数 | 必填 | 说明 |
|------|------|------|
| 项目类型 | 是 | 住宅/公寓/酒店/医院/办公/商业/其他/未提供（按 IC-14 Schema 枚举；"未提供"时输出降低确定性） |
| 验收阶段 | 是 | 材料进场/过程检查/隐蔽工程/分项验收/竣工交付/整改复验 |
| 空间范围 | 是 | 全部楼层/指定楼层/指定户型 |
| 部品系统范围 | 是 | 隔墙/墙面/吊顶/楼地面/厨卫/收纳/机电/全部（数组，至少 1 项，不得默认全部） |
| 上游技能结论 | 条件必填 | 已有上游专项技能分析结论时按契约 §2.2 必传；缺失时标注"上游结论未提供"，仅按通用验收要求生成 |

**响应内容**：验收清单（检查表 + 强制性条文必检项 + 整改闭环表）、必检项覆盖清单、逐项标注 S1/S2/S3 的依据标准、未决事项（存在时必返回）。其中 S1/S2/S3 为本技能 §5 数据来源说明定义的域内三级口径，与合集级 S1–S4 来源分级体系不同，引用时以本技能定义为准。

**约束对应**：必检项不得遗漏（AC-R-P0-1）、不得编造标准（AC-R-P0-2）、隐蔽节点必须列入（AC-R-P0-4）、合格标准量化（AC-R-P1-1）、检验方法可操作（AC-R-P1-2）、依据来源标注（AC-R-P1-3）、部品系统覆盖完整（AC-R-P1-4）。

## 10. 多文件认知架构

## 11. IC-10 标准推理引擎集成调用

本技能在 Step 2（匹配验收标准）中集成调用 IC-10（标准推理引擎），实现标准匹配从静态查表到场景推理的升级。

### 11.1 调用时机与参数

| 项目 | 说明 |
|------|------|
| **触发时机** | Step 2 开始时，确认部品系统范围后 |
| **调用方向** | ACG → prefab-standards-reviewer（SRE） |
| **契约编号** | IC-10（完整定义见 `../shared/interface-contracts.md` §4.4） |

**请求参数**（与 IC-10-Request Schema 字段集一致）：

| 参数 | 必填 | 本技能填充来源 |
|------|------|--------------|
| 引用的标准编号 | 条件必填 | 已知标准编号时传入（如 GB 50210-2018） |
| 引用条文号 | 条件必填 | 已知条文号时传入 |
| 项目所在地 | 是 | Step 0 收集，缺失时默认"全国"并标注 [AC-R-P1-3] |
| 应用场景描述 | 是 | Step 0/Step 1 的项目类型 + 部品系统 + 验收阶段 |

### 11.2 响应使用

SRE 返回的**适用标准集**作为 Step 2~5 的合规基准：

- **适用标准集**：按此筛选 §8 参考标准和 §2.4 必检项中的适用条目，排除不适用的标准
- **标准状态**：废止/替代的标准触发 AC-R-P0-2 防护——不得将已废止标准作为验收依据
- **推理路径**：记录推理链路，在清单备注中引用，便于追溯标准选择依据

### 11.3 SRE 不可用降级

当 SRE 不可用时（接口超时、技能未安装等），按 `shared/interface-contracts.md` §6.1 IC-10 降级策略执行：

1. 使用本技能 §8 参考标准表 + §2.4 强制性条文检查项执行标准匹配
2. 在清单头部标注："SRE 降级：使用 ACG 内置标准映射，标准集未经场景推理筛选"
3. 所有 S1 级标准标注降级为"S1（内置映射，未经 SRE 场景推理验证）"
4. 建议用户在 SRE 恢复后重新生成清单以获得场景化标准筛选

### 11.4 与 SR（IC-07）的分工

- **IC-10（SRE）**：场景化标准集筛选——"这个项目/场景适用哪些标准"
- **IC-07（SR）**：条款级精确核验——"这个具体条款号是否存在、版本是否现行"
- Step 2 优先使用 IC-10 获取标准集；当需要逐条核验条款号准确性时，路由至 `prefab-standards-reviewer`（IC-07）
