## 一、变更分类

所有知识变更按影响范围和紧急程度分为四个级别。

| 变更级别 | 定义 | 典型场景 | 响应时限 |
|---------|------|---------|---------|
| **S 级 — 安全紧急** | 涉及人身安全、标准强制性条文废止或更正，不立即处理可能导致技能输出违反现行法规 | 强制性国标废止/更正、安全红线触发逻辑错误 | **24 小时内**完成影响评估并发布修复 |
| **A 级 — 标准废止** | 推荐性标准或行业标准被废止/替代，技能引用了已失效的条文 | 推荐性国标废止、产品标准被新版替代、地标更新 | **7 日内**完成影响评估和更新 |
| **B 级 — 常规更新** | 新增内容、修正错误、优化表述等不影响安全性的常规变更 | 新增标准收录、术语定义修正、接口参数调整、红线补充 | **当前开发阶段内**完成 |
| **C 级 — 优化调整** | 文档结构优化、措辞改善、格式统一等不影响功能和准确性的变更 | 排版统一、章节重组、说明文字润色 | **按排期处理**，不阻塞当前工作 |

## 二、变更审批流程

所有 B 级及以上的变更须遵循以下四步流程。C 级变更可由变更发起人直接执行，但须记录变更日志。

```
第 1 步：发起变更请求
  └─ 发起人填写变更请求记录（见第八节模板）
  └─ 明确变更级别（S/A/B/C）、变更内容、涉及文件

第 2 步：影响评估
  └─ 评估受影响的技能列表（见第三节影响评估清单）
  └─ 评估需回归测试的用例范围
  └─ 评估向后兼容性（是否存在破坏性变更）
  └─ 评估回滚方式和成本

第 3 步：复核审批
  └─ S/A 级变更：须经 prefab-standards-reviewer 复核 + 变更发起人确认
  └─ B 级变更：须经 prefab-standards-reviewer 复核
  └─ C 级变更：无需复核，但须记录变更日志
  └─ 复核通过标准：变更内容准确、影响评估完整、回滚方案可行

第 4 步：发布与通知
  └─ 执行变更并更新受影响的所有文件
  └─ 更新变更日志（各文件自身的变更日志 + 本文件第九节）
  └─ S/A 级变更须在发布后 24 小时内通知所有受影响技能的维护者
```

## 四、各共享资源的变更专项规则

### 4.1 standards-index.md（标准版本索引）

| 变更类型 | 专项规则 |
|---------|---------|
| 新增标准 | 须经 prefab-standards-reviewer 复核编号、年份、状态；须同步检查"待补充标准清单"中是否已有该条目 |
| 标准废止/替代 | 须同步更新"标准状态变更预警"章节；须在受影响技能的 reference.md 中标注替代关系；S 级（强制性国标废止）须在 24 小时内完成 |
| 标准状态变更（如现行→过渡期） | 须更新状态字段和实施日期；须通知所有引用该标准的技能 |
| 标准编号/年份修正 | B 级变更，须全文扫描确认所有引用该标准的文件均已同步修正 |

### 4.2 glossary.md（专业术语表）

| 变更类型 | 专项规则 |
|---------|---------|
| 新增术语 | 须标注来源标准，经 prefab-standards-reviewer 复核；须检查"待补充术语清单" |
| 术语定义修正 | 须记录变更原因和日期；须全文扫描确认所有引用该术语的技能输出模板无冲突 |
| 术语删除/合并 | A 级变更（可能影响已有技能的意图识别）；须评估对路由逻辑的影响 |
| 多标准定义并列 | 新增地方标准定义时，须标注推荐基准定义，不影响已有定义 |

### 4.3 interface-contracts.md（接口契约）

| 变更类型 | 专项规则 |
|---------|---------|
| 新增接口契约 | 须同时更新"接口契约注册表总览"（第五节）和"技能标识映射"表；新增子技能须先定义全部接口契约 |
| 修改已有接口参数 | 须评估向后兼容性；不兼容变更须升级契约版本号（如 v1.0 → v2.0）；须通知所有调用方和被调用方技能 |
| 删除接口 | A 级变更；须确认无活跃调用方；须提供迁移期和替代方案 |
| 参数格式调整（不改变语义） | B 级变更；须确认所有调用方可解析新格式 |
| 契约版本升级 | 须同步更新本文件**文件头**的版本标记和最后更新日期；须在第七节变更日志中追加版本条目；须检查项目策划方案索引中的版本号引用 |

### 4.4 redlines-registry.md（红线注册表）

| 变更类型 | 专项规则 |
|---------|---------|
| 新增红线 | 须分配全局统一编号（格式：[技能标识]-R-[优先级]-[序号]）；须更新"待注册框架建议" |
| 修改红线触发条件 | A 级变更（可能影响技能安全行为）；须经 prefab-standards-reviewer 复核 + skill-qa-tester 回归测试 |
| 删除红线 | S 级变更（可能移除安全保护）；须经全面影响评估，确认删除不会引入安全风险 |
| 红线编号重排 | B 级变更；须全文扫描确认所有引用该编号的文件均已更新 |

### 4.5 standards-reasoning-rules.md（标准推理引擎规则）

| 变更类型 | 专项规则 |
|---------|---------|
| 锚定标准废止/替代 | **S 级（安全紧急）**。锚定是推理链的承重结构，缺失导致全链路失稳。须在 24 小时内完成替代锚定评估并发布修复；修复前 SRE 对该领域的推理结果须降级标注 |
| 新增标准评估为锚定（满足 C1-C4 准则） | **A 级**。须经 prefab-standards-reviewer 复核入选准则满足性；须同步更新 standards-index.md 的 `is_anchor` 标记 |
| 推理算法步骤修改（M1/M3 模块） | **A 级**。影响全部技能的标准发现行为；须经至少 3 个典型场景回归测试（覆盖住宅/非住宅/地方标准激活） |
| 适用性裁判规则修改（M4 模块） | **B 级**。影响特定场景的标准优先级排序；须验证受影响场景的输出排序无回归 |
| 领域激活表扩展（M3 §3.2 Step 2 新增领域或建筑类型） | **B 级**。须验证新领域与现有领域无交叉冲突；新增行须同步检查 standards-index.md 是否有对应标准收录 |
| 降级与兜底协议修改（M6 模块） | **B 级**。须验证降级行为不引入静默失败；新增降级场景须附测试用例 |
| 锚定标准入选准则不再满足（降级为普通条目） | **B 级**。须选出替代锚定并同步更新 standards-index.md 标记 |

### 4.6 子技能 reference.md（方法论参考文件）

| 变更类型 | 专项规则 |
|---------|---------|
| 材料参数范围修正 | **B 级**。须经 prefab-standards-reviewer 复核数据源；须同步更新数据源置信度等级（S1-S4）标注；若涉及 IC-08/IC-09 构造描述字段，须检查接口契约兼容性 |

## 五、跨文件变更协调规则

当一次变更同时影响多个共享资源或技能文件时，须遵循以下协调规则。

**原子发布原则**：同一次变更涉及的所有文件修改须作为一个整体发布，不得分批发布导致中间状态不一致。例如，新增一条标准同时影响 standards-index.md 和某技能的 reference.md，两个文件须同步更新。

**引用方向原则**：变更沿引用方向传播。当共享资源（被引用方）发生变更时，须主动检查所有引用方是否需要同步更新。当引用方的引用内容发生变更时，须确认被引用方未发生变化。

**冲突优先原则**：当两个变更同时影响同一文件且存在冲突时，按变更级别优先级处理（S > A > B > C）；同级别变更按发起时间先后处理。

## 六、定期审查机制

| 审查类型 | 频率 | 执行者 | 审查内容 |
|---------|------|--------|---------|
| 标准状态巡检 | 每季度 | prefab-standards-reviewer | 对 standards-index.md 全部标准执行状态检查（现行/废止/过渡期），确认无遗漏 |

## 七、紧急变更快速通道

S 级（安全紧急）变更可走快速通道，简化审批流程但保留关键控制点：

```
快速通道流程：
  1. 发起人直接执行变更（跳过第 1 步表单填写）
  2. 变更后 24 小时内补齐影响评估清单
  3. prefab-standards-reviewer 事后复核（48 小时内）
  4. 如复核发现问题，立即回滚并走正常流程
```

**快速通道适用条件**（须同时满足）：
- 变更级别为 S 级
- 变更内容明确（如标准废止有明确的替代标准）
- 回滚成本可控（如可通过 git revert 回退）
