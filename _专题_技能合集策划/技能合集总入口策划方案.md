## 装配式装修技能合集总入口策划方案

### 核心定位

**总入口是路由引擎和协同调度器，不是知识技能。**

总入口的核心能力是"理解用户意图 → 精准匹配技能 → 协调多技能协同 → 整合输出"。它本身不包含装配式装修的专业领域知识（隔声、耐火、构造做法等），这些知识由各子技能承载。总入口需要的是"元知识"——对每个子技能的能力边界、职责范围和协同关系的准确理解，以及对装配式装修行业术语体系的掌握。

```
用户输入
  │
  ▼
总入口（意图识别 + 路由决策）
  │
  ├──→ 单技能路由：直接分发至目标子技能
  │
  ├──→ 多技能协同：分解任务 → 调度多个子技能 → 整合输出
  │
  ├──→ 术语查询：调用共享术语库 → 返回定义和上下文
  │
  └──→ 越界拒绝：识别超范围问题 → 说明边界 → 建议替代路径
```

### 一、技能合集架构总览

#### 1.1 子技能分类体系

技能合集中的子技能按职责分为五个角色层级：

| 角色层级 | 技能名称 | 职责定位 | 知识深度 |
|---------|---------|---------|---------|
| **专项技能** | prefab-partition-wall-solution | 装配式隔墙系统的选型方法论与方案验证 | 深：完整决策树+验证协议 |
| | prefab-wall-surface-system | 装配式墙面系统的选型与工艺推荐 | 深：4D分类矩阵+7大知识域 |
| | prefab-ceiling-system | 装配式吊顶系统的选型与机电协同 | 中：场景选型+构造逻辑 |
| | prefab-floor-system | 装配式楼地面系统的选型与隔声减振 | 中：场景选型+构造逻辑 |
| | prefab-bathroom-kitchen-system | 装配式厨卫系统的选型与防水排水接口 | 中：场景选型+接口逻辑 |
| | prefab-storage-system | 装配式收纳系统的选型与空间接口 | 中：模块化配置+接口逻辑 |
| **跨系统技能** | prefab-mep-integration-system | 机电管线分离、跨部品接口协调、安装顺序 | 中：冲突检测+接口矩阵 |
| | prefab-acceptance-checklist-generator | 基于专项技能输出生成验收清单 | 中：清单生成逻辑 |
| **通用技能** | prefab-interior-materials-expert | 全领域通用咨询、标准查询、质量诊断 | 广：7大知识域+6种输出模板 |
| **质量工具** | prefab-standards-reviewer | 规范标准复核（指标、引用、术语一致性） | 专：5阶段审查方法论 |
| | skill-qa-tester | 技能质量测试（功能、数据、红线） | 专：5阶段测试方法论 |
| **外部协作** | waterproofing-expert | 建筑防水工程（属外部技能合集） | 中：分层响应模型 |

#### 1.2 技能间的关系原则

**独立性原则**：每个子技能可独立运行，不依赖总入口的存在。用户直接调用任何子技能时，该技能应能自主完成工作。总入口是"便捷通道"，不是"必需通道"。

**知识不重叠原则**：各子技能的知识领域应尽量避免重叠。当存在不可避免的交叉地带（如隔墙与墙面的交界），由各技能的边界规则明确分工，而非各自重复覆盖。

**共享基础设施原则**：以下内容作为合集级共享资源，不在各子技能中重复维护：
- standards-index.md（标准版本索引）
- glossary.md（专业术语表，详见第五节）
- interface-contracts.md（跨技能调用接口契约）
- redlines-registry.md（全合集红线统一编号注册表）
- change-governance.md（知识变更治理规则）
- platform-adapter-reference.md（平台适配参考）

### 二、总入口核心逻辑

#### 2.1 意图识别框架

总入口接收到用户输入后，首先执行意图识别，将用户意图分类为以下七种类型：

| 意图类型 | 判断特征 | 路由目标 |
|---------|---------|---------|
| **A. 单部品系统咨询** | 用户问题聚焦于某一个部品系统（如"隔墙怎么做""吊顶用什么材料"） | 对应专项技能 |
| **B. 跨部品系统咨询** | 用户问题涉及两个以上部品系统的接口或协同（如"卫生间防水与地面的关系""吊顶与墙面的收口"） | 多技能协同流程 |
| **C. 术语/概念查询** | 用户询问专业术语的含义、区别或适用条件（如"什么是管线分离""干法作业和湿法的区别"） | 共享术语库 |
| **D. 全领域通用咨询** | 用户问题跨多个系统但不需要深度专项分析，或涉及行业趋势、政策、综合方案（如"装配式装修的整体流程""装配率怎么计算"） | prefab-interior-materials-expert |
| **E. 规范标准查询/复核** | 用户询问特定规范条文、标准版本有效性、指标合规性 | prefab-standards-reviewer 或 prefab-interior-materials-expert |
| **F. 质量诊断/问题排查** | 用户描述了施工质量问题或使用缺陷，需要诊断原因 | 根据涉及的部品系统路由至对应专项技能，或 prefab-interior-materials-expert |
| **G. 技能测试/元操作** | 用户要求测试技能质量、复核标准、更新技能内容 | skill-qa-tester 或 prefab-standards-reviewer |

**意图模糊时的处理**：当用户输入无法明确归入某一类型时，总入口应主动追问，而非猜测路由。追问策略：
- 列出2-3个可能的意图方向，请用户确认
- 如仍无法确定，默认路由至 prefab-interior-materials-expert（通用技能），由其进一步引导

| 歧义场景 | 判断规则 |
|---------|---------|
| "隔墙与墙面"同时提及 | 区分问题焦点：隔墙本体（隔声/耐火/构造）→ 隔墙技能；墙面饰面（调平/饰面板/收口）→ 墙面技能；两者均有 → 多技能协同 |

#### 2.3 多技能协同规则（意图类型B）

当用户问题涉及多个部品系统时，总入口启动多技能协同流程。

**协同流程（七步法）**：

```
第1步：任务分解
  └─ 总入口分析用户问题 → 识别涉及的部品系统 → 确定需要调用的子技能列表

第2步：上下文建立
  └─ 总入口提取并整理用户提供的统一上下文（项目类型、空间类型、约束条件等）
  └─ 将统一上下文传递给每个被调用的子技能

第3步：专项分析（并行）
  └─ 各专项技能独立输出各自系统的分析结果
  └─ 输出格式遵循各技能自身的输出模板

第4步：版本一致性校验（新增）
  └─ 总入口检查各子技能输出中引用的标准版本是否一致：
     - 同一标准是否被不同技能引用了不同版本（如一个引用GB 50118-2010，另一个引用地方标准的不同指标）
     - 各技能引用的标准状态是否均为"现行有效"（参考A0标准状态管理）
     - 评价量是否一致（如隔声评价量Rw+C vs Rw+Ctr vs DnT,w+C）
  └─ 如发现版本不一致：
     - 标注冲突的标准引用及各自来源
     - 以效力层级更高的标准为准（强制性国标 > 地方标准 > 推荐性标准）
     - 当项目所在地地方标准严于国标时，提示用户确认执行哪个标准
  └─ 调用 shared/standards-index.md 校验各标准的状态字段（现行/废止/过渡期）

第5步：跨系统审查
  └─ 调用 prefab-mep-integration-system 审查：
     - 管线分离策略是否一致
     - 各系统间的接口是否冲突
     - 安装顺序是否合理

第6步：标准复核（如适用）
  └─ 调用 prefab-standards-reviewer 审查高风险标准引用的准确性

第7步：整合输出
  └─ 总入口汇总各技能输出 → 识别冲突和待确认事项 → 整合为统一回复
  └─ 如用户需要，调用 prefab-acceptance-checklist-generator 生成验收清单
```

> **六步法升级为七步法的说明**：原六步法在第3步（专项分析）和第4步（跨系统审查）之间缺少对标准引用一致性的检查。新增的第4步"版本一致性校验"填补了这一盲区，确保各子技能在引用标准时不会出现版本冲突或引用已废止标准的情况。该步骤的实施依赖 `shared/standards-index.md` 中的标准状态字段（详见隔墙技能v2方案A0标准状态管理）。

**冲突处理规则**：当多个子技能的输出存在矛盾时（如隔墙技能建议的龙骨间距与墙面技能建议的饰面板安装要求冲突），总入口应：
- 明确标注冲突点
- 分析冲突原因（通常是假设条件不同）
- 建议用户确认具体参数后由相关技能重新分析
- 不做"仲裁"——仲裁需要领域知识，应由子技能之间的协商完成

> **仲裁边界说明（2026-06-28 补充）**：上条"不做仲裁"特指**专业技术结论仲裁**——总入口不具备领域知识，不得替代子技能做隔声达标判定、构造方案选型等专业结论。但总入口**应当执行流程性仲裁**，包括：红线优先级裁决（子技能输出触发 P0 标记时的处理顺序）、路由边界裁决（意图归属有争议时的最终路由决定）、输出确定性等级裁决（❓/✅/⚠️ 标记的保留与提升）、缺失信息裁决（多技能协同时信息不足时追问哪一方补充）。流程性仲裁是总入口的职责，不可下放给子技能。

#### 2.4 术语查询路由（意图类型C）

当用户询问专业术语时，总入口从共享术语库（glossary.md）中检索并返回定义。

| 查询类型 | 处理方式 |
|---------|---------|
| 单术语定义（如"什么是管线分离"） | 直接返回术语定义+来源标准+使用上下文 |
| 术语辨析（如"干法作业和湿法的区别"） | 返回相关术语定义+对比分析 |
| 术语在特定场景下的含义（如"隔墙中的管线分离怎么理解"） | 返回术语定义+路由至对应专项技能做场景化解释 |

| "北京项目能不能用浙江地标？" | 地方标准适用性 | 调用 SR | 按项目所在地判断，不适用时仅作对比参考 |
| "这个厂家说能达到 60dB，可以直接用吗？" | 产品数据验证 | 路由至 PW | 不采信厂家单方宣传，要求检测依据和构造一致 |
| "帮我推荐一个品牌隔墙系统。" | 产品推荐倾向 | 路由至 PW 并降级 | 不做品牌推荐，只给选型方法和验证清单 |
| "这是防火墙还是防火隔墙？" | 安全红线辨析 | 路由至 PW | 触发防火墙边界提示，必要时建议消防专业 |
| "承重墙可以拆掉换成装配式隔墙吗？" | 超越边界/结构安全 | 明确拒绝替代结构判断 | 引导结构专业机构，不路由为普通隔墙选型 |
| "帮我出消防审查意见。" | 超出资质边界 | 说明边界 | 可协助整理问题清单，不出审查结论 |
| "墙太薄但又要很隔音怎么办？" | 约束冲突 | 路由至 PW | 要求列出厚度、目标 dB、空间类型并提示权衡 |
| "我不知道是墙面问题还是隔墙问题。" | 模糊意图 | 追问 | 列出墙面饰面、基层、隔声/开裂等方向供确认 |
| "装配式装修整体怎么做？" | 全领域通用咨询 | 路由至 ME | 不让总入口自行展开完整专业知识 |
| "帮我把这个方案做验收清单。" | 验收清单生成 | 调用 AC，必要时先让专项技能验证 | 未经专项验证的项目列为待确认项 |
| "测试一下隔墙技能有没有问题。" | 技能测试/元操作 | 调用 QA | 使用统一测试状态：计划/已执行/补跑通过/未执行/不适用 |

**样例使用规则**：样例只用于路由判断和追问设计，不作为专业答案模板。涉及隔声、耐火、防火、构造、造价、验收等专业结论时，必须交由对应子技能或质量工具输出。

### 三、总入口红线体系

#### 3.1 红线优先级分层

与隔墙技能的三层红线体系（P0/P1/P2）保持架构一致，总入口红线分为两个层级：

| 优先级层级 | 定义 | 触发后行为 |
|-----------|------|----------|
| **P0 路由安全红线** | 涉及路由准确性、用户信息安全和系统可信度的核心底线 | **立即纠正路由行为**，确保用户不被引导至错误方向 |
| **P1 协同规范红线** | 涉及多技能协同质量、输出一致性和运营规范的约束 | 在当前输出中标注并修正，保证协同流程的完整性 |

#### 3.2 完整红线清单（8条）

**P0 路由安全红线（5条）**

| 编号 | 红线 | 说明 | 触发后标准应对话术 |
|------|------|------|-----------------|
| OR-P0-1 | 严禁越俎代庖 | 总入口不得自行回答需要专业领域知识的问题，必须路由至子技能 | "该问题涉及[部品系统]的专业技术领域，我将为您转接至[子技能名称]进行专业分析。" |
| OR-P0-2 | 严禁伪造路由依据 | 路由决策必须基于用户输入的实际内容，不得编造用户未提供的信息 | "我注意到您的描述中未明确[关键信息]，为避免路由错误，请您确认：[追问]" |

| OR-P0-5 | 严禁篡改子技能输出 | 整合子技能输出时不得改变其结论的含义或确定性等级 | 如子技能输出标注为"❓ 预估满足"，整合时不得升级为"✅ 满足" |

#### 3.3 红线冲突仲裁规则

| 冲突场景 | 仲裁规则 |

### 五、专业术语体系设计

#### 5.1 定位与重要性

专业术语是装配式装修技能合集的**认知基石**。术语定义不准确或不统一，将导致技能在意图识别、路由判断、输出表达等各环节出现偏差。术语体系不仅服务于总入口的意图理解，也服务于所有子技能在输出中保持一致的专业表达。

#### 5.2 术语组织框架

术语按五个层级组织，从核心概念到专项术语递进展开。

> **覆盖范围说明**：以下各层级所列的术语定义仅为重点引用和推荐关注，不代表装配式装修涉及的全部术语。技能须具备全面理解和运用装配式装修专业术语的能力，能够识别和解释未在下方表格中列出的其他术语。当遇到未列举的术语时，技能应能根据其所属层级判断其类别，并结合来源标准给出准确定义。
>
> **地标差异处理原则**：不同地方标准（国标、行标、各地地标如北京DB11/T、广东DBJ/T 15、浙江设计导则、福建DBJ/T 13等）对同一术语可能存在不同的描述或定义侧重。术语表中的定义为推荐基准定义，优先采用国标/行标（JGJ/T 491-2021、GB/T 51129-2017等）的定义；当项目所在地有适用的地方标准时，技能应能识别该地标中的术语差异，并在输出中注明"该术语在[地标编号]中的表述为：……，与国标定义的区别在于……"。术语表鼓励在同一术语条目下并列列出不同标准的定义版本，以便技能在实际应用中灵活适配。

**第一层：核心概念（装配式装修的定义与理念）**

| 术语 | 定义 | 来源标准 |
|------|------|---------|
| 装配式内装/装配化装修 | 遵循管线与结构分离的原则，采用干式工法，将工厂生产的标准化内装部品、部件在现场进行组合安装的装修方式 | JGJ/T 491-2021（2.0.1） |
| 室内装修部品（内装部品） | 按照一定的边界条件和配套技术，在工厂生产，由两个及以上单一产品、材料或复合产品组合而成，能满足室内装修一项或多项功能要求的产品。 | DB11/T 1553-2025 |
| 部件 | 在工厂或现场预先生产制作完成，构成建筑结构系统的结构构件及其他构件的统称 | JGJ/T 494-2022 |
| 通用部品部件 | 满足尺寸定型要求，可按照标准尺寸规模化生产、规范化安装的系列化部品部件，是通用部品和通用部件的统称 | JGJ/T 494-2022 |

|------|------|---------|
| 管线分离 | 建筑结构体中不埋设设备及管线，采取设备及管线与建筑结构体相分离的方式 | JGJ/T 491-2021（2.0.2） |
| 标准化设计 | 采用标准化部品部件、标准化接口进行建筑集成设计的方法 | DBJ 46-061-2021 |
| 集成设计 | 统筹不同专业、不同系统的技术要求，协调系统与系统之间、系统内部、部品部件之间的连接,协调设计、生产、供应、安装、运维不同阶段的需求,前置解决设计问题的过程 |  JGJ/T 491-2021（2.0.4）|

#### 5.3 术语体系的技能应用规则

**术语一致性规则**：总入口和所有子技能在输出中使用专业术语时，应以 glossary.md 中的定义为基准。当 glossary.md 中列出了多个标准的不同定义时，应根据项目所在地的适用标准选择对应定义；当项目所在地无特殊要求时，以国标/行标定义为默认基准。不得自行编造或引用非标准定义。当技能遇到 glossary.md 中未收录的术语时，应基于其训练知识给出专业理解，并标注"该术语定义未在 glossary.md 中收录，建议查阅相关标准确认"。

**术语辨析能力**：总入口应具备以下易混淆术语的辨析能力：

| 易混淆对 | 区分要点 |
|---------|---------|
| 装配式隔墙 vs 装配式墙面 | 隔墙是分隔空间的结构体（非承重墙体），墙面是附着在已有墙体表面的饰面系统 |
| 集成卫生间 vs 整体卫生间 | 集成式是在现场采用干式工法施工的卫生间，整体式是工厂预制的完整模块（含防水底盘、壁板、顶板及支撑龙骨等） |
| 管线分离 vs 管线预埋 | 管线分离是管线与结构体分开设置（SI理念），管线预埋是管线埋入结构体 |
| 干式工法 vs 干作业 | 干式工法是装配式装修的核心建造方法（体系概念），干作业是具体施工方式（操作概念） |
| 可逆安装 vs 可拆装 | 可逆安装强调安装方式的可逆性（可拆可装不破坏），可拆装强调部品本身的可拆卸更换能力 |
| 标准化设计 vs 集成设计 | 标准化设计关注部品部件尺寸规格的模数化和统一化，集成设计关注多系统（结构+围护+机电+内装）的一体化 |
| 工厂预制 vs 工厂化生产 | 语义基本一致，"预制"更强调提前制造，"工厂化"更强调生产方式的工业化转型 |

**术语更新机制**：glossary.md 作为合集级共享资源，其更新需经 prefab-standards-reviewer 复核确认。新增术语时必须标注来源标准，修改术语时必须记录变更原因和日期。当发现同一术语在不同标准中存在定义差异时，应在该条目下并列列出各版本的定义，标注各自来源，并注明推荐基准定义。

```
- [引用的标准编号和条款]

[标准免责提示]
```

#### 6.2 子技能间的交叉路由规则

各子技能在执行过程中，当发现用户问题涉及相邻系统时，应在输出中标注"跨系统接口"，由总入口决定是否启动协同流程。

| 发起技能 | 触发条件 | 目标技能 |
|---------|---------|---------|
| 隔墙技能 | 用户询问墙面饰面与隔墙基层的适配 | 墙面技能 |
| 墙面技能 | 用户询问墙面饰面对隔墙结构的要求 | 隔墙技能 |
| 吊顶技能 | 用户询问吊顶与隔墙/墙面的收口 | 隔墙/墙面技能 |
| 楼地面技能 | 用户询问地面与湿区防水的接口 | 厨卫技能 |
| 厨卫技能 | 用户询问湿区防水工程技术问题 | 外部防水技能 |
| 收纳技能 | 用户询问入墙式收纳对隔墙的要求 | 隔墙技能 |
| 任何专项技能 | 用户询问标准条文的有效性或合规性 | standards-reviewer |
| 任何专项技能 | 用户问题超出该技能的专业边界 | materials-expert（通用兜底） |

#### 6.3 子技能输入参数标准格式（新增）

为确保总入口与各子技能之间、以及子技能相互之间的数据传递格式统一，定义以下标准输入参数结构。所有子技能在接收任务时，应以该格式解析输入；总入口在分发任务时，应按该格式组织上下文。

**标准输入参数结构**：

```
【任务来源】
来源类型：[总入口路由 / 子技能交叉路由 / 用户直接调用]
来源技能：[发起方技能名称，若为总入口则标注"orchestrator"]
原始用户输入摘要：[用户原始问题的简明复述，不超过100字]

【统一上下文（必传字段）】
项目类型：[住宅/酒店/医院/学校/办公/商业/其他]
空间类型：[具体空间，如：客房/分户墙/走道/卫生间等]
约束条件列表：
  - 空间约束：[墙体厚度限制、层高等，若无则标注"未提供"]
  - 功能约束：[管线分离/挂载/拆卸等需求，若无则标注"未提供"]
  - 成本约束：[目标造价区间，若无则标注"未提供"]
  - 工期约束：[施工速度要求，若无则标注"未提供"]
  - 环境约束：[潮湿/高温/洁净等，若无则标注"未提供"]
已知性能指标：[已明确的隔声/耐火/防火等指标，若无则标注"未提供"]

【上游技能分析结论（可选字段，交叉路由时必传）】
上游技能名称：[已执行的子技能名称]
上游分析结论摘要：[上游技能的核心结论]
待本技能确认的事项：[上游技能在"跨系统接口"中提出的具体问题]
已知风险/待确认事项：[上游技能标注的⚠️/❓项]

【调用请求】
期望输出类型：[专项分析 / 验证评估 / 成本分析 / 术语解释 / 其他]
优先级：[高（安全相关）/ 中（功能相关）/ 低（参考信息）]
```

> **使用说明**：
> - **必传字段**（统一上下文）：所有子技能在启动分析前，必须从输入中获取这些字段。若字段缺失，子技能应主动向调用方（总入口或上游技能）请求补充，而非自行假设。
> - **可选字段**（上游分析结论）：仅在交叉路由场景下必传。总入口在启动多技能协同时，应将上游技能的分析结论按此格式传递给下游技能，确保上下文连贯。
> - **参数格式的平台无关性**：该结构以纯文本/Markdown形式定义，不依赖特定平台的API或数据结构，任何AI Agent平台均可解析。

#### 6.4 跨技能调用接口契约清单（新增）

以下为当前技能合集中已规划的跨技能调用接口的最小参数集定义，统一收录在 `shared/interface-contracts.md` 中。各技能开发时须按此契约实现输入/输出接口。

| 调用关系 | 调用场景 | 发起方须传递的最小参数集 | 接收方须返回的最小结果集 |
|---------|---------|----------------------|----------------------|
| 总入口 → 隔墙技能 | 单技能路由（意图类型A） | 统一上下文（6.3必传字段）+ 用户隔墙相关问题描述 | 隔墙技能标准输出（6.1格式）|
| 总入口 → 隔声计算引擎 | 隔墙技能请求隔声计算 | `{板材类型[], 厚度[], 面密度[], 空腔深度[], 填充材料, 龙骨类型, 连接方式, 密封方式}` | `{隔声估算区间, 吻合效应风险, 声桥风险等级, 密封评估, 构造合理性意见}` |
| 隔墙技能 → 墙面技能 | 用户询问饰面与隔墙基层适配 | 统一上下文 + `隔墙基层类型`（石膏板/硅酸钙板/其他）+ `隔墙构造总厚度` + `已确认的隔墙性能指标` | 墙面技能标准输出 + `对隔墙基层的要求`（平整度/握钉力/含水率）|
| 墙面技能 → 隔墙技能 | 用户询问饰面对隔墙结构的要求 | 统一上下文 + `预定饰面类型` + `饰面重量（面密度）` + `对基层的要求` | 隔墙技能标准输出 + `基层适配性评估` |
| 收纳技能 → 隔墙技能 | 用户询问入墙式收纳对隔墙的要求 | 统一上下文 + `收纳系统尺寸（宽×高×深）` + `预估挂载重量` + `安装方式` | `隔墙基层承载力评估` + `加固建议` + `构造限制说明` |
| 任何技能 → standards-reviewer | 标准条文有效性/合规性复核 | `引用的标准编号` + `引用条文号` + `项目所在地` + `应用场景描述` | `标准状态`（现行/已废止/过渡期）+ `合规性意见` + `替代标准建议（如已废止）` |
| 总入口 → materials-expert | 全领域通用咨询（兜底路由） | 统一上下文 + 用户问题原文 | materials-expert标准输出（6种输出模板之一）|

> **契约治理规则**：
> - 接口契约由 `shared/interface-contracts.md` 统一维护，任何技能新增或修改接口时，须同步更新该文件并经 `prefab-standards-reviewer` 复核。
> - 新增子技能在纳入合集前，必须先定义其与已有技能的接口契约，确保系统集成的一致性。
> - 接口契约中的参数格式变更须向后兼容，或通过版本号管理（如v1.0→v1.1），避免破坏已有技能的调用链路。
