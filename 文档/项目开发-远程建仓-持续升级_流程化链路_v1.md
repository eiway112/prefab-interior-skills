# 项目开发 — 远程建仓 — 持续升级 流程化链路 v1.0

> **文件定位**：从装配式装修技能开发项目（2026-06～08，CG-001～003）实践中提炼的通用流程链路，适用于长周期、多文档、多技能/多模块协作的项目管理。
> **三原则**：安全（可回滚、审计留痕）、高效（最短路径、幂等工具）、必要性（不过度设计、不重复修订）。
> **最后更新**：2026-08-14

---

## 阶段 A：项目初始化（一次性）

### A1 建立治理骨架（必要性：高）

项目目录按业务逻辑组织，至少包含以下要素：

| 要素 | 作用 | 本项目实例 |
|------|------|-----------|
| 权威源声明 | 明确冲突时以谁为准 | AGENTS.md（SOT 定义） |
| 治理文件区 | 红线/契约/变更规则的单一事实源 | `_专题_技能合集策划/` + `技能仓备份/shared/` |
| 成果区 | 交付物最短路径（≤3 层） | `成果/` |
| 索引文件 | 全项目文档地图，每行带状态列 | `文档/项目策划方案索引.md` |
| 程序文件区 | 幂等脚本（同步/校验/测试） | `程序文件/` |

### A2 远程建仓（安全：高）

1. `git init` + 首个 commit（显式 `git add` 具体文件，不用 `add -A`）
2. GitHub 建仓，确认公开/私有边界——公开仓只暴露应对外发布的子目录（本项目为 `技能仓备份/`）
3. 建立 README + CHANGELOG + License（对外口径三件套）
4. 记录 push 凭据方案：`GIT_TERMINAL_PROMPT=0` + Windows 凭据管理器；github.com 直连受阻时用 `https_proxy=socks5h://127.0.0.1:10808`，代理不可用时降级等待，不强行绕过

### A3 版本基线

打 v1.0.0 tag 作为对外发布基线，CHANGELOG 记录基线内容。

## 阶段 B：开发执行（每批次）

### B0 Pre-flight 计划预审（安全：最高优先级）

每次任务开始前强制执行：

1. 读取文件管理规范 + 治理手册（任务前置读取协议）
2. 判定任务等级 L0-L3（依据：文件改动/真实资产/不可逆/批量范围/外部副作用）
3. 输出预审摘要：目标 / 交付物 / 输出路径 / 验收等级 / 关键风险 / 用户确认点 / 最小成功标准 / 中止条件
4. 不可逆操作（删除、覆盖、迁移）必须经用户确认，且有回滚路径（git 可恢复 或 备份快照）

### B1 变更定级（必要性：高）

按 change-governance 四级分类：

- **S 级**：安全紧急（标准废止影响安全结论）——立即停手上报
- **A 级**：标准废止/推理算法修改——用户显式确认
- **B 级**：常规更新（红线注册、契约调整、技能升版）——用户既有授权即可
- **C 级**：优化调整（措辞、格式、索引修正）——顺手可做但须登记

每批次分配 CG 编号：`CG-YYYYMMDD-序号`，写入 change-governance.md 变更日志。

### B2 执行纪律

1. **备份先行**：破坏性修改前打 `_pre<日期><CG编号>` 快照（版本控制下的文件豁免）
2. **显式暂存**：`git add <具体文件>`，永不 `add -A` / `add .`
3. **计数链同步**：凡涉及计数的文档（头部总数/映射表/统计摘要/变更日志），一次改全，改后全链核对
4. **历史只追加**：CHANGELOG、CG 日志、备忘录的历史条目永不改写，新事实用新条目覆盖旧结论
5. **范围纪律**：只做本批次 CG 声明范围内的事，发现的无关问题记入观察项，不顺手修

### B3 提交与打 tag

1. commit message 格式：`<版本>: <批次主题>（CG-编号）` + 正文分条列明变更
2. NEW COMMIT over AMEND——永不改写已提交历史
3. 每个发布批次打 tag：`git tag v<版本>`
4. 注意：`--follow-tags` 只推附注 tag，轻量 tag 须 `git push origin <tag>` 显式推送

### B4 Push 前全文复核（安全：结构性变更时必做）

结构性变更（技能增删、计数体系调整、文档迁移）push 前执行八维复核：

| 维度 | 检查内容 |
|------|---------|
| 计数链 | 头部/映射表/统计摘要/变更日志数字一致 |
| 数字残留 | 全局搜索旧数字（如"16个技能"），区分历史记录与活跃文档 |
| 引用残留 | 被移除对象的引用分类：应清除 vs 应保留（跨模块路由/历史记录） |
| 契约一致性 | 标识映射/枚举/路由表无残留 |
| 索引基线 | 索引文件的基线数据与实际一致 |
| CHANGELOG | 版本条目与 commit 一致，序列连续 |
| 镜像哈希 | 各层副本 sha256 一致 |
| 新项目完整性 | 迁出/新建目录的文件清单完整 |

复核结论 PASS 才允许 push；WARN 项修复后追加 commit（tag 移至修复后的 commit）。

## 阶段 C：远程建仓与发布（每批次）

### C1 Push

```
GIT_TERMINAL_PROMPT=0 git push --follow-tags
# 轻量 tag 补推：git push origin <tag>
```

网络失败处理：代理重试 → 降级等待 → 记入待办，commit 永不丢（本地仓是完整账本）。

### C2 发布验证（必要性：高）

1. `git ls-remote --tags origin` 确认 tag 到达远程
2. 对照 CHANGELOG 确认版本描述与实际变更一致
3. 公开仓检查对外暴露面（只有应发布的目录可见）

## 阶段 D：持续迭代（长期）

### D1 迭代入口检查（每轮对话开头）

1. `git status` 确认工作区干净
2. 查索引与 CHANGELOG 最新状态，确认上轮收尾位置
3. 长期记忆回顾：治理环境、已知坑、待办事项

### D2 漂移防控

1. **镜像同步**：多副本文件每次变更后哈希比对（sha256），漂移即修
2. **幂等脚本**：同步/校验/测试脚本化（sync_skill_backup.py、validate_governance.py、QA 测试脚本），可重复执行不产生副作用
3. **QA 基线**：关键技能建测试基线（TestDocAnchor 模式：文档间三向比对），版本更新后回归跑
4. **定期复核**：结构性变更后全文复核（见 B4）；日常小变更靠计数链纪律

### D3 噪音治理（长周期项目核心）

| 机制 | 做法 |
|------|------|
| 权威层级 | AGENTS.md 定义 SOT，冲突按层级裁决 |
| 治理账本 | CG 编号 + CHANGELOG 构成审计链，判断结论有效性看"其后有无新 CG 推翻" |
| 状态标识 | `_归档库/` 只放结项内容；`_pre*` 后缀=变更前快照；索引每行带状态列 |
| 日期锚定 | 评估报告/备忘录是时点快照，只取时点结论不取现行规则 |
| 引用纪律 | 引用历史文档时标注日期和 CG 编号，不裸引 |

### D4 拆分与迁出（项目膨胀时）

当某模块业务归属与主项目不一致时（如 WF 之于装配式装修）：

1. 评估迁出 ROI（治理缺口 vs 适配成本）
2. 新建独立项目目录（含 README 治理五问：入口/权威源/交付物/可重建项/敏感项）
3. 主项目内清理：标识映射/统计行/契约枚举/备份脚本/运行时安装
4. 保留必要的跨模块路由引用（外部协作指向）
5. 走完整 CG + 复核 + push 流程

## 阶段 E：安全红线（贯穿全程）

1. **永不永久删除用户文件**：只进回收站，删后验证落地
2. **破坏性修改先备份**：`_pre*` 快照或依赖 git 可恢复
3. **敏感文件不进仓**：显式 add、不提交 `.env`/凭据
4. **历史不可改写**：不改写已提交 commit、不改写历史 CHANGELOG/CG 条目
5. **外部副作用须确认**：对外发布、运行时安装变更、跨项目迁移，用户确认后才执行
6. **失败不硬闯**：推送/连接失败记录后停止重试，不强行绕过安全机制
